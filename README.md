# Dyadic Plugins

[Skills](https://github.com/HiLleywyn/dyadic-skills) · [Agents](https://github.com/HiLleywyn/dyadic-agents) · [Plugins](https://github.com/HiLleywyn/dyadic-plugins)

Dyadic's 40 default plugin descriptors, browsable under [dyadic/](dyadic/README.md). Each descriptor identifies a Store item and the built-in tool switch it controls (for example `weather.*` or `workspace.*`). The tools themselves are implemented by the Dyadic server; a descriptor is not an executable plugin, MCP server or skill, and carries no backend code or credentials.

A plugin being listed is distinct from its being enabled, configured, authorized and successfully run. Account switches, provider configuration, connected services, approvals and billing remain enforced by the platform.

## Layout

| Path | Contents |
| --- | --- |
| [dyadic/](dyadic/README.md) | One folder per plugin: `plugin.json` (official snapshot) and a README describing the capability, permissions and required configuration |
| [catalog.json](catalog.json) | Machine-readable inventory, regenerated by `tools/catalog.py index` |
| [provenance.json](provenance.json) | Dyadic source path and SHA-256 for every `plugin.json` |
| [COMPATIBILITY.md](COMPATIBILITY.md) | What Dyadic does and does not do with these descriptors |
| `tools/catalog.py` | Shared index/check/build tool (identical in the agents, plugins and skills repos) |
| `tests/`, `.lley/run.py` | Offline unittest suite and the JUnit-verifying runner used by CI |

## Validate and build

Requires Python 3.11+ and PyYAML.

```sh
python -m pip install PyYAML
python tools/catalog.py check   # metadata, switch IDs, versions, links, provenance hashes
python .lley/run.py             # test suite; writes reports/catalog.xml and fails on any skip
python tools/catalog.py build   # dist/<plugin-id>.zip, dist/checksums.json, dist/collection.zip
```

`check` validates each tool switch pattern, requires the latest `changes` entry to match `version`, rejects broken relative links in any `README.md`, and rejects a changed `plugin.json` without a matching `provenance.json` update. The archives are deterministic descriptor bundles for distribution; Dyadic's skill/agent importer does not accept them as executable plugins.

## Maintenance

1. `plugin.json` files are snapshots of Dyadic's `catalog/plugins/<id>/plugin.json`. Change the runtime capability and its manifest in Dyadic first, then copy the committed manifest here and update its hash in `provenance.json`. There is no automated sync tool for this repository, and editing a README here cannot add a tool to the server.
2. Keep each folder's README consistent with its manifest (name, switch, permissions) and update the [dyadic/ index](dyadic/README.md) when names or descriptions change.
3. Run `python tools/catalog.py index`, then `check`, `.lley/run.py` and `build`.
4. `tools/catalog.py`, `tests/` and `.lley/run.py` are shared with dyadic-agents and dyadic-skills. Apply changes to all three and run each repository's checks.

## CI

[.github/workflows/ci.yml](.github/workflows/ci.yml) runs `python .lley/run.py` and `python tools/catalog.py build` on every push and pull request. `.lley/pipeline.json` declares the same stage for the lley.cat mirror's runner. Neither deploys anything or changes Dyadic's Store.
